# Проект 3 спринта SQL. Обработка 
## Условия задач
### 1 Часть - знакоммство с данными

1. Начните с данных о клиентах и их тарифном плане. Выгрузите первые 20 строк с информацией о пользователях и проверьте, что данные соответствуют описанию.

2. Проверьте, что в данных для каждого пользователя нет пропусков. В результат запроса должны войти строки, которые содержат хотя бы один пропуск в любом поле таблицы. При этом не учитывайте только поле `user_id` — это первичный ключ таблицы, и в нём не может быть пропусков. Выгрузите первые 10 строк итоговой таблицы.

3. Посчитать долю активных клиентов.

4. Проверьте, что за весь период у каждого активного клиента был только один тарифный план. В запросе не забудьте отфильтровать данные и оставить только активных пользователей — тех, у кого в поле `churn_date` стоит пропуск.
Выведите ID клиентов, у которых больше одного тарифного плана и количество тарифных планов у клиентов

5. Познакомьтесь с данными об услугах, которыми пользовались клиенты. Для начала взгляните на данные о длительности звонков. Проверьте, встречаются ли в этих данных пропуски, — выведите все строки таблицы `calls`, в которых встречаются пропуски в любом из полей, то есть в `duration` или `call_date`.

6. Проверьте возможные аномалии в данных о длительности разговора — определите минимальное и максимальное значения. Назовите столбцы `min_duration` и `max_duration` соответственно.

7. Проверьте возможные аномалии в данных о длительности разговора — определите минимальное и максимальное значения. Назовите столбцы `min_duration` и `max_duration` соответственно.

8. Теперь изучите общую длительность разговоров каждого пользователя в день — встречаются ли случаи, когда суммарная длительность превышала 24 часа. Эта проверка поможет оценить корректность данных. 
Для каждого клиента посчитайте длительность всех звонков за день, переведите это значение в часы и выведите топ-10 клиентов с высокими значениями общей длительности разговоров.
Результат запроса должен включать такие поля:
`user_id` — идентификатор клиента;
`call_date` — дата звонка (данные уже приведены к нужному типу, менять тип данных не надо);
`total_day_duration` — суммарная длительность всех звонков клиента за день в часах.

### 2 Часть - Расчеты

1. Выгрузите данные о клиентах с информацией о потребляемых услугах за каждый месяц активности и посчитайте их месячные траты на действующем тарифном плане.
Для решения задачи посчитайте и выведите в новом обобщённом табличном выражении `users_costs` следующие данные:  
`user_id` — идентификатор клиента;  
`dt_month` — месяц статистики;  
`tariff` — название тарифного плана клиента;  
`month_duration` — суммарная длительность всех разговоров клиента в этом месяце;  
`month_mb_traffic` — суммарное количество потраченных мегабайтов интернет-трафика в этом месяце;  
`month_sms` — общее количество отправленных клиентом сообщений в этом месяце;  
`rub_monthly_fee` — абонентская плата по тарифному плану;  
`total_cost` — сумма общих трат клиента в этом месяце: сюда входят абонентская плата и платы за активность сверх тарифного плана — минуты разговоров, гигабайты и сообщения, которые не вошли в лимит.  

2. Рассчитать средние траты в месяц для активных клиентов, которые продолжают пользоваться услугами компании, в разрезе тарифного плана.
Рассчитайте уникальное количество клиентов и средние траты по тарифу. Для этого используйте результат обобщённого табличного выражения `users_costs`. Среднее значение трат по каждому тарифу округлите до двух знаков после точки.   
Задачу решите в основном запросе с такими полями:  
`tariff` — название тарифного плана клиента;  
`total_users` — количество клиентов;  
`avg_total_cost` — значение средних ежемесячных трат клиентов по тарифу.

3. Для каждого тарифного плана посчитайте уникальных активных клиентов, чьи ежемесячные траты превышают абонентскую плату по тарифу. Выведите также их средние траты в месяц и среднее значение переплаты.
Задачу решите в основном запросе с такими полями:  
`tariff` — название тарифного плана клиента;  
`total_users` — количество клиентов;  
`avg_total_cost` — средние ежемесячные траты клиента по тарифу;  
`overcost` — переплата клиента относительно ежемесячного платежа.  
Полученные значения округлите до двух знаков после точки.
